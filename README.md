# 発電どうぶつ — HATSUDEN WORKS

新方式の内部テスト版は `1.0 (5)` です。[TestFlightビルド5の確認項目](Release/TestFlight-build5.md)を参照してください。

[Hatsuden.xcodeproj](Hatsuden.xcodeproj) をXcode 26.1で開き、`Hatsuden` スキームでiOS 17以降のiPhoneを選んで実行します。

現在は、車輪が転がって溜まる方式へ変更中の開発版です。ビルド4で作成した [公開素材](Release/README.md) は旧配置の記録で、新方式の公開前に掲載文と画像を更新します。

- 連打で左のゲージを溜めます。発電フロアでは複数の指でタップしても、指ごとに数えます。70%に達したタップから、ゲージが70%以上の間はタップ1回につき全個体が1回発電します。
- どうぶつはZの目で眠り、タップを続けると起きて、小走りから走りに変わります。タップを止めるとゲージは徐々に下がります。
- アプリを閉じている間は120秒につき通常の発電1回分の割合で所持金が増えます。復帰時は閉じる前の所持金から、留守中に増えた分を数え上げて表示します。所持金と所持数は従来のセーブから引き継ぎます。
- 売店はバスケットのボタンで全画面に開きます。前の種類を1体迎えると次が解放され、所持金が足りれば購入できます。同じ種類も購入数のゲーム上限なく追加できます。未解放の種類は「???」と黒いシルエットで表示します。
- 購入した動物は、右上の投入口から回し車ごと転がり込みます。床や車輪にぶつかり、乱雑に溜まっていきます。大きい新種や箱の混み具合に合わせて箱と視界を広げます。昔の小さい動物を買い足した場合も、その時点の縮尺のまま点のように入ってきます。
- 車輪は円形として衝突し、落ち着いた車輪の移動計算は休ませます。車輪の移動と、中で眠ったり走ったりする動物の見た目を分けています。購入数と収益の記録は、描画や衝突計算の簡略化から独立しています。
- 2本指のピンチは指の中心を基準に拡大・縮小し、2本指を一緒に動かすと見たい場所へ移動できます。短い複数指タップは発電として数え、移動を伴うカメラ操作と区別します。青い矢印で全景に戻ります。
- 揺らすボタンを押すと箱の中の車輪を動かせます。続けて押すと揺れが重なり、小さい個体も含めて混ざります。揺らす操作そのものには発電収益を付けません。車輪の位置を並べ直して混ぜる処理は使いません。
- 車輪の配置は所持金とは別に保存します。通常のセーブと同じUserDefaults領域を使い、再開時に配置を復元します。旧セーブから所持金、購入済み動物、購入数を引き継ぎます。
- 所持金は一行で、100万円未満は全桁、100万円以上はSI接頭語付きで表示します。接頭語の範囲を超える金額は指数表記です。保存と読み上げには正確な金額を使います。
- 背景は、透明な発電箱の向こうに広がる一続きのクレヨン画です。ハムスターハウスのある室内から、机のパソコン、庭、街、山、港、宇宙へと視界が広がります。背景と車輪を同じカメラで動かすので、好きな場所へ寄っても縮尺と位置が揃います。背景の建物や山には衝突せず、箱と車輪が当たり判定を持ちます。
- プレイ画面と売店の一番下に320 × 50 ptのバナー広告が入ります。
- BGMにはMintoDogの「Cozy Puzzle In-Game 1」を使用しています。売店の音符ボタンでオン・オフを切り替えられます。 [配布元](https://opengameart.org/content/cozy-puzzle-in-game-1) · [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/deed.ja)

### 進行の目安

新しい種類の1体は、前の種類の1体の9倍を発電します。たとえば新規プレイのホタルは1,920円で、ミツバチ8体なら240回分、1体なら1,920回分の発電です。この8体は価格バランスの比較用の目安で、所持上限や解放条件ではありません。追加購入の価格は所持数に応じて増え、9体目以降も購入できます。

新規プレイではミツバチから、成体の代表的な大きさを目安に小さい順に解放します。大きさはゲーム用の概算で、主に全長を使い、キリンなどは高さ、脚の長いカニなどは脚を含めた寸法を使っています。足つきサメは大型のサメをモデルに約4.8 m、発電怪獣と銀河発電竜は架空の寸法です。既存セーブは購入済みの動物と順番を維持し、未購入分を小さい順に並べます。 [大きさと素材IDのデータ](Hatsuden/AnimalCatalog.swift) · [NOAAのホホジロザメ資料](https://www.fisheries.noaa.gov/species/white-shark/science) · [ロンドン自然史博物館のティラノサウルス資料](https://www.nhm.ac.uk/discover/dino-directory/tyrannosaurus.html)

売店の体長と、ゲーム内の車輪の直径は別データです。車輪は体長を参考にしながら解放順に大きくし、ほぼ同じ体長の種類にも差を付けます。隣り合う種類で極端に飛ぶ寸法も調整し、投入時の引きが一度に大きくなりすぎることを抑えます。 [車輪の寸法](Hatsuden/PileWheelSizes.swift)

### 広告

視聴完了後に、選んだ発電量が5分間2倍になります。「連打発電」は閾値を超えたタップに適用します。「留守中の発電」はバックグラウンドにいた時間のうち有効期間と重なる分に適用し、効果中はプレイ画面でもどうぶつが起きています。2種類は同時に使えます。終了時刻はセーブされます。

アプリ起動時広告は、広告設定後の3回目以降のコールド起動で、最大4秒の読み込み中に取得できたときに表示します。バナーはプレイ画面と売店の下部に固定し、連打やスクロールの操作エリアとの間に余白を確保します。両画面で同じ広告ユニットを使います。 [起動時広告のガイド](https://developers.google.com/admob/ios/app-open?hl=ja) · [バナーの配置ガイド](https://support.google.com/admob/answer/6275335?hl=ja)

#### 初めてのAdMob設定

1. [AdMob](https://admob.google.com/) にログインし、「アプリ」から iOS アプリとして「発電どうぶつ」を追加します。App Storeにまだ掲載していなければ、掲載済みかの質問で「いいえ」を選びます。 [アプリの登録手順](https://support.google.com/admob/answer/9989980?hl=ja)
2. アプリ内の「広告ユニット」で、形式を「リワード」にして **連打発電2倍** と **留守中発電2倍** の2枠を作ります。報酬の数は `1`、報酬アイテムは `5分ブースト` にします。Google AdMobのみで配信する場合、パートナーでの入札はオフのままにします。 [リワード枠の作成手順](https://support.google.com/admob/answer/7311747?hl=ja)
3. 「広告ユニットを追加」から、形式が「アプリ起動時広告」の **アプリ起動** と、形式が「バナー」の **下部バナー** を1枠ずつ作ります。 [起動時広告枠の作成手順](https://support.google.com/admob/answer/9620632?hl=ja) · [バナー枠の作成手順](https://support.google.com/admob/answer/7311346?hl=ja)
4. アプリIDと4枠の広告ユニットIDを [Info.plist](Hatsuden/Info.plist) に入れます。 [IDの確認手順](https://support.google.com/admob/answer/7356431?hl=ja)

| コピーする値 | 設定先 |
| --- | --- |
| アプリID（`ca-app-pub-…~…`） | `GADApplicationIdentifier` |
| 連打用の広告ユニットID（`ca-app-pub-…/…`） | `HatsudenTapRewardAdUnit` |
| 留守中用の広告ユニットID（`ca-app-pub-…/…`） | `HatsudenBackgroundRewardAdUnit` |
| 起動時広告のユニットID（`ca-app-pub-…/…`） | `HatsudenAppOpenAdUnit` |
| バナーのユニットID（`ca-app-pub-…/…`） | `HatsudenBannerAdUnit` |

Debugでは各形式のテスト用IDを使います。本番配信に向けては、AdMobの「プライバシーとメッセージ」で必要な同意メッセージを設定し、App Store公開後にストアの掲載情報をリンクして審査を受けます。アプリは設定済みの同意メッセージを必要に応じて表示します。 [テスト広告](https://developers.google.com/admob/ios/test-ads?hl=ja) · [同意メッセージの設定](https://developers.google.com/admob/ios/privacy) · [配信準備の審査](https://support.google.com/admob/answer/10564477?hl=ja)

## テストと負荷計測

**Product → Test**（⌘U）で、200種それぞれの絵とシルエット、解放順、セーブの互換性、9体以上の購入と復元、発電、留守中の収益、ブースト、カメラ、配置とポップアップを検証します。

Debugの実行引数に `--stress-particles` を追加すると、通常のセーブから独立した計測用データ（200種類 × 8体、計1,600体）で毎秒10タップを再現します。この個体数は計測用の基準で、購入上限ではありません。コンソールの `Hatsuden particle stress` にシーン更新頻度とポップアップ数が出ます。

`--pile-demo` では、通常のセーブと別に38種類を複数体ずつ持った確認用の箱を開きます。自由ズームと揺らすボタン、売店からの追加投入を確認できます。起動時広告はこの確認用モードでは表示しません。両方の引数はDebug専用です。

購入数にゲーム上の上限はありませんが、端末のメモリと描画能力には限りがあります。点サイズの車輪同士は衝突を簡略化し、見える大きさの車輪との接触、個々の位置、全員分の収入と発電ポップアップは保持します。重いフレームでは物理演算の追いつきを最大2ステップに抑え、操作を長く止めないようにしています。実機での描画を含む60〜120fpsの検証は別途必要です。新方式のApp Store向け検証は開発中です。
